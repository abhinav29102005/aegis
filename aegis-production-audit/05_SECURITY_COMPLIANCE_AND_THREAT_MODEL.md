### 1.3 AI Agent & Prompt Injection Assessment (Phase B4)
- **What IS protected (`VERIFIED IN CODE`):**
  1. `PurchasingCopilot` (`guardian/agents/purchasing_copilot.py:130-151`) holds **zero** references to DB sessions, repositories, PayPal secrets, or `BudgetCoordinator`; calling `authorize()`/`approve_budget()`/`capture_payment()` raises `AgentSecurityViolationError`.
  2. `Role.AGENT_SERVICE` (`packages/security/security/auth.py:88-95`) has `PROPOSALS_WRITE`, `PAYMENTS_READ`, `PAYMENTS_CHECKOUT`, `PAYMENTS_CAPTURE` — **NOT** `APPROVALS_DECIDE`, `PASSPORTS_WRITE`, `AGENTS_WRITE`, or `KEYS_MANAGE`.
  3. **Can an AI agent bypass deterministic controls *via direct purchasing tools*?** No in the current Guardian API path — `PolicyEngine` & `BudgetCoordinator` gate every `POST /v1/guardian/proposals`, and PayPal keys stay server-side. **HOWEVER**, two indirect bypass vectors exist right now:
     - **A2A / UI / Tool escalation (`CRITICAL`):** Due to `SEC-01`, an `AGENT_SERVICE` key can invoke all `/v1/ghostpay/*` routes; and if a compromised human approver sends `{"approved": false}`, bug `SEC-11` approves the payment anyway! Also `AGENT_SERVICE` holds `PAYMENTS_CAPTURE` (`auth.py:92`), enabling an agent to trigger PayPal capture after checkout without separate server/payer-confirm gate if `buyer-approved` was spoofed (no PayPal redirect token/order status verification inside `handle_buyer_approved`!).
     - **No real LLM guardrails tested in prod (`MISSING`):** Neither `PurchasingCopilot` (claimed LangGraph) nor `DisputeAnalyzer` (LLM reviewer) implements live LLM calls (`LLM_PROVIDER=deterministic`), cost/token budgets, model-version provenance logging on proposals, eval datasets, or prompt-injection filtering on `item_summary`/`rationale`/`buyer_claim`. `CitationValidator` (`citations.py:70-75`) is easily bypassed via short substring excerpts (`"USD"`) alongside arbitrary claims and unverified `llm_summary` text!

## 2. Regulatory & Standards Applicability Separation
*(Technical engineering mapping — NOT formal legal advice; flagged for qualified fintech legal counsel.)*

| Framework / Standard | Applies to Current Architecture (Control Plane / No Card PAN / No Fund Custody)? | Triggered by Future Expansion (MoR / Wallets / Card Issuing / Geographies)? | Current Evidence & Gaps in AEGIS |
| :--- | :--- | :--- | :--- |
| **PCI DSS v4.0.1** | **Minimal / Out-of-Scope CDE IF kept strictly free of cardholder PAN/CVV** (PayPal JS SDK / hosted redirect handles payment credentials). *Note:* Next.js frontend scripts serving payment/checkout pages using embedded provider JS SDKs require merchant script inventory/integrity monitoring under v4.0.1 **Reqs 6.4.3 & 11.6.1** (effective Mar 2025). | **Full Third-Party Service Provider (TPSP) RoC / Level 1 QSA audit** triggered immediately if AEGIS ever transmits, routes, stores, or processes raw PAN/CVV across multiple gateways. | **VERIFIED:** No PAN/CVV fields in `contracts/` or `orm.py`. **GAP:** No CSP / Subresource Integrity (SRI) / script-monitoring headers on `apps/web` (`Reqs 6.4.3/11.6.1`). |
| **US FinCEN MSB / State MTL** | **Likely exempt (`Payment Processor / Pure SaaS`) ONLY IF** AEGIS never takes custody of funds, never pools/settles payouts, and merely instructs third-party processors (`PayPal`, `Stripe`). *Legal review required.* | **Federal MSB registration + ~48-state MTLs** (or BaaS sponsor bank partnership) required for custodial agent wallets, escrow/pooled balances, or peer-to-peer transfers. | **VERIFIED:** Current code reserves virtual DB budget counters only; funds move strictly via PayPal merchant APIs. |
| **EU PSD2 / SCA & E-Money** | SaaS analytics/governance layer does not trigger PSP licensing; buyer checkout SCA (`3DS` / PayPal login) is handled on PayPal's hosted checkout surface. | **Payment Initiation / Account Info / E-Money license** required for initiating bank open-banking transfers directly or issuing EU e-money wallets/cards. | **PARTIAL:** `handle_buyer_approved` trusts caller POST rather than verifying PayPal `GET /orders/{id}` payer status (`COMPLETED`/`APPROVED`) before trusting approval! |
| **India RBI Payment Aggregator (PA) & Data Localization** | Applies if operating as an online PA collecting & pooling customer funds for Indian merchants; pure technical SaaS orchestration without fund pooling generally falls to Partner PA flow-down requirements (certifications, security posture). | **Mandatory RBI PA authorization, Rs 15–25 Cr net-worth rules, & strict India payment-data localization** if handling Indian domestic fund settlement/pooling. | **GAP:** Zero multi-region data residency pinning (`Postgres` location agnostic); zero Indian PSP/UPI rails. |
| **GDPR & India DPDPA 2023** | **APPLICABLE TODAY** whenever processing PII of EU or Indian users/employees/buyers (`users.email`, `full_name`, `dispute_cases.buyer_claim`, `admin_audit_logs`, uploaded dispute artifacts containing customer addresses/receipts). | Expanded **DPO / DPBI breach notification / cross-border transfer SCCs / DPAs** at commercial scale. | **GAP:** Zero consent tracking, zero Right-to-Erasure / PII anonymization workflow (`DELETE /v1/users/me` or dispute PII redaction), unenforced `retention_until`, unencrypted evidence/audit text. |
| **OWASP ASVS v4 & API Top 10 (2023)** | **APPLICABLE ENGINEERING BASELINE TODAY.** | Same + external penetration testing. | **GAPS:** API1 (artifact BOLA), API2 (secret/JWT env mismatch, localStorage, no key status check), API4 (global rate-limit collision), API5 (GhostPay RBAC missing, ADMIN->OWNER escalation), API7 (webhook SSRF), API9 (unmounted insecure routers). |
| **SOC 2 Type II / ISO 27001** | **Voluntary Enterprise Trust Certification** (expected by B2B mid-market/enterprise buyers during vendor security review). | Mandatory commercial gate for enterprise contracts (`> $25k–$100k ACV`). | **GAP:** Missing centralized SIEM/log retention, SSO/MFA, RBAC separation-of-duties, formal SDLC PR approvals/SBOM, DR/BCP tabletop logs, change-management controls. |
| **AML / KYC / Sanctions (OFAC/UN)** | Basic **KYB/sanctions screening on onboarded orgs/merchants** advisable if acting as multi-tenant payment gateway/orchestrator; PSP (`PayPal`/`Stripe`) performs underlying settlement KYC/sanctions. | **Full CIP/KYC/KYB, OFAC screening, SAR filing, transaction monitoring** mandatory if becoming MoR, PayFac, or wallet issuer. | **GAP:** Zero merchant/org KYB verification or sanctions list screening (`POST /v1/auth/register` is wide open to anyone). |

**Counsel Escalation Flags:** Qualified fintech legal counsel should review (1) whether multi-tenant agent spending governance + orchestrated checkout triggers US/EU "money transmission" or "payment initiation" under specific enterprise contract flows, (2) GDPR/DPDPA PII erasure vs immutable SHA-256 financial event hash-chains (crypto-shredding PII keys vs hashing salted tokens!), and (3) PayPal/Stripe API Terms of Service compliance when acting on behalf of merchant tenants.
